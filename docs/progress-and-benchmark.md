# Nado Agent Progress and Open-Source Benchmark

Snapshot date: 2026-08-21

## Executive assessment

Nado already satisfies the core definition of a cross-terminal, cross-machine Agent gateway for trusted Ubuntu/WSL-style workers:

- control is available through HTTP, CLI, MCP, generated `AGENTS.md`, and a browser Dashboard;
- workers connect outbound, advertise capabilities, labels, tool inventory, concurrency slots, and resource diagnostics;
- shell and terminal-Agent tasks can be routed to explicit workers or scheduled by capability/tool/label/capacity;
- sessions preserve worker/workspace affinity, while batches support dependencies and parent artifact handoff;
- task events, artifacts, cancellation, retry, offline recovery, worker management, and signed worker identities are implemented;
- GPU-aware routing distinguishes an observed NVIDIA/AMD SMI probe from an advertised-only capability.

This is more than a scheduling demo, but it is not yet a highly available, hostile-multi-tenant production platform. Its current sweet spot is a trusted team or individual coordinating a small fleet of heterogeneous machines.

## Capability boundary

| Area | Current state | Assessment |
| --- | --- | --- |
| Cross-terminal control | CLI, MCP, Dashboard, HTTP, generated agent context | Ready |
| Cross-machine execution | Outbound worker polling, bootstrap/fixed-ID bundles, preflight, systemd/Windows/macOS persistent service installers | Ready for LAN/VPN/public control deployments |
| Cross-hardware routing | Inventory-backed OS/CPU-architecture selectors, capabilities, labels, tools, weighted slots, CPU/RAM/GPU/VRAM/model reservations, structured GPU probes | Resource-aware admission implemented; real heterogeneous-host acceptance remains |
| Agent runtimes | Codex, Claude, custom command, demo echo | Ready when worker credentials and CLI inventory are verified |
| Durable orchestration | JSON or embedded SQLite-compatible store, batches, sessions, attempts, artifacts, heartbeat single-writer lease, commit-time fencing | Ready for one crash-recoverable control process; not active/active |
| Cross-site data transfer | Inline compatibility plus resumable input/output chunking, persisted offsets, ranged Worker downloads, restart resume, per-chunk and whole-file SHA-256 | Implemented; multi-GB object-storage offload remains optional future work |
| Operational telemetry | Cross-platform CPU utilization/RAM pressure/load, data-volume capacity, previous-heartbeat control RTT, bounded upload/download samples, NVIDIA, modern AMD SMI, and legacy ROCm GPU metrics, best-effort Linux thermal-zone/hwmon, Windows hardware-monitor/ACPI, and optional macOS `osx-cpu-temp` temperatures | Implemented; further platform sensor providers remain |
| Failure recovery | Attempt leases, heartbeat renewal, bounded retry/backoff, idempotent submission keys, automatic ordinary-task recovery, same-Worker session recovery, stale-attempt guards, reconnect backoff, ordered/idempotent live-event delivery, durable completion-delivery retry | At-least-once; external command effects should be idempotent |
| Security | Admin/Worker/enrollment identities, Ed25519 request signatures, replay protection, durable audit export plus external NDJSON mirroring, request/rate guards, strict Dashboard CSP/headers | Suitable for trusted networks behind TLS; no RBAC/tenant isolation |
| Isolation | Per-task workspaces and isolated environment profile | Convenience boundary only; not a container/VM sandbox |
| High availability | Single control process and embedded store | Not implemented |

## Comparable open-source projects

The projects are similar in different layers; none is a drop-in equivalent.

| Project | Useful idea for Nado | Difference |
| --- | --- | --- |
| [OpenHands](https://github.com/OpenHands/OpenHands) | Agent-centric run workspace, runtime separation, live execution feedback | Primarily a software-development agent platform, not a lightweight heterogeneous worker scheduler |
| [Ray](https://github.com/ray-project/ray) | Resource-aware scheduling, cluster observability, explicit task/actor/object abstractions | Much broader distributed compute runtime with a Python-first ecosystem |
| [Prefect](https://github.com/PrefectHQ/prefect) | Run-state clarity, retries, event-driven recovery, operator-first workflow monitoring | Data workflow orchestration rather than terminal-Agent execution |
| [Dagster](https://github.com/dagster-io/dagster) | Dependency visualization, lineage, inspectable execution history | Asset/data-pipeline model rather than remote shell/Agent workers |
| [Dify](https://github.com/langgenius/dify) | Progressive disclosure and approachable workflow UX | LLM application/workflow platform rather than machine-level dispatch |
| [Vibe Kanban](https://github.com/BloopAI/vibe-kanban) | Task-centric planning/review and workspace-centric Agent UX | Coding-agent project manager; its repository currently announces sunset, so it is an interaction reference rather than a foundation choice |

## Improvements applied from the benchmark

### Dashboard

- Added a four-stage `Prepare → Route → Execute → Result` indicator so an Agent run has one obvious lifecycle.
- Added synchronized task search across Workbench and Tasks views.
- Reduced summary-card density and added an automatic-recovery readiness card.
- Kept detailed routing/resource controls behind the existing progressive-disclosure panel.
- Added an always-visible Cross-Site Topology that presents the live control instance/start time, SQLite state/schema versions, restore receipt/manifest digest, and every Worker's control-observed source, protocol, gateway state, capabilities, and authentication evidence without implying that local or unsigned connections have passed production acceptance.
- Expanded the Cross-Site Acceptance operations panel to download the evidence template, generate all nine automated/supervised exercise commands plus the strict final gate, quote backup-path placeholders safely, apply the selected Worker/GPU requirement consistently, and copy the complete runbook to the clipboard.
- Added an authenticated live acceptance-report endpoint and Dashboard gate. Operators can run the non-mutating live checks alone or explicitly include the target-pinned end-to-end verify tasks, then inspect automatic failures separately from mandatory real-pair evidence, follow concrete next actions, and download the JSON report. Local/loopback, administrator-token, plain-HTTP, or recovery-disabled demos remain visibly failed instead of being mistaken for production readiness.

### Core service

- Added exponential worker reconnect backoff with jitter and a configurable maximum to avoid retry storms during control-plane outages.
- Separated task execution from result transport: Workers retain the slot and live attempt while retrying transient completion delivery, recognize a replay after a lost success response, stop on permanent HTTP errors, and surface retry/recovery/rejection/exhaustion events. A SQLite restart fault-injection test proves one execution and preserved stdout across a short control outage.
- Made live stdout/stderr delivery WAN-resilient without unbounded buffering. Per-attempt events carry stable IDs and sequence numbers through an ordered 256-entry queue; response-loss replay deduplicates at Control, while overflow, stale rejection, or one exhausted queue-level retry budget short-circuits the remaining chunks and attempts one explicit `output_delivery_gap` before terminal result delivery. Tests cover replay after a committed response loss, ordering through transient failure, queue bounds, and bounded failure time.
- Added opt-in automatic recovery of non-session tasks after a configurable offline grace period.
- Exposed recovery policy and at-least-once semantics through status and capabilities responses.
- Preserved existing attempt IDs and stale-result rejection so a superseded worker cannot overwrite recovered work.
- Added execution leases renewed by worker heartbeat; an expired lease cannot be resurrected and late events/results are ignored.
- Added per-task `maxAttempts`, bounded exponential recovery delay, `retry_exhausted` terminal state, and submission `idempotencyKey` deduplication.
- Added default-off transient process-failure retry policies with classified timeout/process/Worker/non-zero failures, exact exit-code matching, cross-platform native exit-code preservation, capacity release, distinct attempts, and explicit retry/exhaustion events.
- Added a concrete VM-to-home-worker guide for private Tailscale/WireGuard and public HTTPS/Caddy deployment, including a real two-host acceptance matrix.
- Added CPU/RAM/GPU-count/VRAM/model admission and reservation accounting shared by dispatch preview, scheduler, and worker claim.
- Added first-class operating-system and CPU-architecture admission across CLI, HTTP, MCP, Dashboard, sessions, batches, dispatch preview, and claim-time enforcement. Common Windows/macOS and amd64/aarch64 aliases normalize to Worker inventory values; missing or mismatched evidence fails closed with exact route reasons instead of relying on manually maintained labels.
- Added bounded CPU-utilization and memory-pressure score penalties after hard admission, letting automatic routing prefer a less loaded equivalent host without overriding explicit targets, session affinity, or declared resource guarantees.
- Added structured NVIDIA GPU inventory plus idle-worker long-poll claims with immediate task wakeup and fixed-poll compatibility mode.
- Added structured AMD/ROCm JSON inventory for model, total/free VRAM, edge/junction temperature, and utilization through the same vendor-neutral resource scheduler.
- Added modern `amd-smi` discovery and merged static/metric JSON parsing for AMD model, decimal/binary VRAM units, free/used memory, preferred edge temperature, and graphics utilization. Successful AMD SMI output takes precedence over legacy `rocm-smi` so one physical device is not reported twice.
- Added streaming, resumable large-output uploads with persisted offsets, chunk and whole-file SHA-256 checks, atomic finalization, stale-attempt rejection, and post-upload workspace cleanup.
- Added task-gated large-input uploads plus attempt-bound ranged Worker downloads; CLI and Dashboard select the path automatically and dependency artifacts no longer require another base64 copy.
- Added filesystem-native Worker disk telemetry, previous-heartbeat control RTT, and bounded best-effort Linux thermal-zone/hwmon plus Windows LibreHardwareMonitor/OpenHardwareMonitor WMI temperature probes with ACPI fallback across CLI, generated context, capabilities, and Dashboard Worker detail. Linux class symlinks are accepted, invalid or missing sensor values are filtered, duplicate thermal-zone/hwmon readings prefer the more descriptive hwmon source, and duplicate Windows monitor identifiers prefer LibreHardwareMonitor.
- Added a bounded, non-privileged macOS CPU-temperature probe through an already-installed `osx-cpu-temp` command. Missing executables, unsupported Intel/Apple Silicon sensors, timeouts, diagnostics, and invalid readings degrade to no sample without affecting Worker registration or task execution.
- Added per-Worker CPU-time delta sampling that works on Windows where load averages are unavailable, plus normalized memory used/free percentages. Heartbeats retain legacy fields, while CLI, Dashboard, capabilities, and generated Agent context surface the structured measurements without inventing a utilization value for the first sample.
- Added Worker-initiated bounded upload/download probes with payload integrity checks, identity binding, a 1 MiB ceiling, per-direction control-side rate limiting, configurable sampling, and non-fatal failure behavior.
- Added persisted, redacted audit events with CLI/Dashboard NDJSON export and an optional ordered external NDJSON mirror whose failures are isolated and path-free health is observable. Its configurable pending bound prevents a stalled sink from growing memory without limit, while delivery-integrity diagnostics preserve evidence that an external backfill is required; identity/IP rate limits, bounded JSON parsing, strict Dashboard CSP/security headers, and graceful audit flush remain enabled.
- Added explicit logical-state and SQLite schema versions plus offline full-directory backup, SHA-256 manifest verification, safe fresh-directory restore, and persisted artifact/input path remapping.
- Added a strict cross-site acceptance report that combines live remote-URL, transport, Worker identity, SQLite, recovery, telemetry, optional GPU/Agent, and target-pinned verify checks with mandatory operator evidence for the physical WAN scenarios. Reports pass only when every required gate passes.
- Exposed the complete stateless evidence lifecycle as MCP `nado_acceptance_template`, `nado_record_acceptance_evidence`, and `nado_acceptance_report`, including optional target-pinned verification and structured manual evidence input. A control-side Agent can now obtain the canonical template, validate one observed result without VM-local file access, and feed the unchanged document into the strict gate; the surface preserves the separation between automatic checks and mandatory operator WAN/physical evidence.
- Added a target-pinned remote-cancellation acceptance exercise that waits for the exact Worker command acknowledgement and a post-process `task_released` event, then writes structured task/attempt/event references into the strict evidence file.
- Added a target-pinned two-turn Agent collaboration exercise that requires verified real terminal-Agent readiness, proves session/workspace handoff with a random marker, validates plan/final/transcript artifacts, closes the session, and records structured evidence while rejecting demo or unverified Agents.
- Added a supervised short-WAN-disconnect exercise that binds an operator-triggered heartbeat gap to the target task's unchanged attempt/lease, proves renewal before expiry and one execution, validates the returned artifact, and distinguishes supervised evidence from fully automated exercises.
- Added a supervised long-WAN-disconnect exercise plus immutable attempt environment variables. It proves first-attempt execution, lease-expiry recovery, stale-result rejection, scheduler-selected second-attempt success, and an attempt-2 artifact while explicitly preserving at-least-once semantics.
- Added a supervised VM-control-restart exercise with non-persisted control instance IDs. It requires an observed outage and new instance, proves SQLite task/attempt durability and home-Worker reconnection, and verifies one execution plus the returned artifact hash; a real same-port SQLite restart integration test covers the complete local fault-injection path.
- Added administrator-visible, storage-path-redacted per-task artifact-upload progress and a supervised large-artifact resume exercise. It binds a real Worker heartbeat gap to a stable committed offset, requires the same upload/attempt to finalize after reconnect, and verifies a deterministic source hash by direct download; the integration test blocks the real Worker transport after its first committed chunk and then restores it.
- Added durable attempt-bound input Range events and a supervised large-input resume exercise. It stages a deterministic input on the VM, observes the Worker's initial request, requires a heartbeat gap, then proves the same attempt requests a positive offset after reconnect and hashes the complete input correctly; the integration test interrupts a real response body after partial local persistence.
- Added path-free restore receipts and a supervised backup/restore exercise. Restore receipts are created only after verified files are copied, state paths remapped, and the restored store saves successfully; old receipts are excluded from subsequent backups. The exercise proves a new control instance uses a fresh receipt, preserves pre-backup history/artifacts, reconnects the Worker, and accepts new work from the restored SQLite directory.
- Hardened acceptance under loaded control planes: a not-yet-created artifact upload is no longer mistaken for a completed `0/0` upload, and offline backup ignores only the store's recognized atomic-write temporary filenames so an abandoned or concurrently disappearing state temp file cannot corrupt the snapshot walk.
- Bound cross-site identity acceptance to the selected Worker's latest successful registration/heartbeat authentication evidence, preventing administrator-token or unsigned-token Workers from passing based only on gateway-wide signed-identity support.
- Added per-Worker control-observed source/transport evidence with explicit trusted-proxy semantics, Dashboard/CLI/context visibility, and a non-loopback acceptance gate so a local Worker cannot pass from a public-looking advertised URL alone.
- Bound encrypted-transport acceptance to the selected Worker's observed protocol, rejecting direct HTTP behind an advertised HTTPS URL while preserving operator-verified Tailscale/WireGuard HTTP overlays.
- Added `worker inspect`, a control-independent home-host readiness gate for Node.js, writable data storage, tools, CPU/RAM, vendor-probed GPU/VRAM/model, configured Codex/Claude runtime, and matching Ed25519 enrollment identity. Strict requirements return exit code 2 and its JSON evidence omits credentials and private keys.
- Integrated that gate into self-service startup as opt-in CLI/API/MCP policy and a default-on Dashboard bundle option. Strict bootstrap checks declared GPU/real-Agent prerequisites before enrollment, validates the persisted identity after signed preflight, and regenerates rather than reuses a corrupt or mismatched keypair when a fresh enrollment credential is available.
- Hardened credential-revocation acceptance so operator prose alone cannot pass. Rotation now records a structured non-secret receipt; the strict report binds it to the selected Worker's current replacement token, requires an observed predecessor HTTP 401, and cross-checks control-triggered evidence against the durable completed Worker command.
- Hardened remote-cancellation acceptance so a handwritten pass cannot satisfy the final gate. Signed Worker cancellation/application and process-release events carry stable event IDs, retry transient delivery failures, and are idempotently copied into the exact task's durable history; the report binds that history to the selected Worker and attempt. Ordered acceptance reads prevent a new Worker event from being paired with a stale task snapshot at a timeout boundary, while immutable HTTP claim snapshots preserve attempt identity when cancellation races the claim save. SQLite restart coverage proves the correlation remains durable after a replay. This avoids losing final acceptance evidence during WAN faults or when the bounded general Worker-event log rotates.
- Hardened Agent-collaboration acceptance so an edited evidence document cannot stand in for real terminal-Agent work. The report now cross-checks the selected Worker, closed affinity session, two successful Agent attempts, and exact plan/final/transcript artifact metadata against durable control state.
- Hardened short-disconnect acceptance with VM-computed observation receipts. The control endpoint now validates the live target task/Worker/attempt, derives heartbeat age itself, rejects expired leases, persists attempt-bound gap and recovery events, and accepts recovery only after the same lease advances; the strict report binds those events to the one-execution artifact instead of trusting edited age/timestamp fields.
- Hardened long-disconnect acceptance by binding the supervised receipt to the selected Worker, exact two-attempt task, lease-expiry recovery event, stale-result rejection, first-attempt execution marker, and final artifact digest. The local CLI integration fixture now remains pending when this real WAN drill has not run instead of claiming completion from prose.
- Hardened VM-restart acceptance by server-stamping each API-created task with its actual creation runtime ID. The report now requires that stamp to match the old instance, the live status to report a distinct restarted instance after an observed outage, SQLite to preserve the single attempt, the Worker to heartbeat after restart, and the returned one-execution artifact to match durable metadata.
- Hardened both large-transfer acceptance paths. Artifact chunk commits/finalization now create durable task offset events, allowing the report to prove a persisted partial offset, real stalled interval, same upload/attempt recovery, and final digest. Input resume binds the staged descriptor to the existing attempt-authorized offset-0 and positive Range events plus the Worker hash artifact. Local evidence without these supervised WAN events remains pending.
- Hardened backup/restore acceptance by binding the supervised receipt to the live verified restore receipt, old/new runtime IDs, server-stamped pre-backup and post-restore tasks, preserved marker and new write-probe artifact digests, plus the selected Worker's post-restart heartbeat. Edited receipt fields or recycled task evidence cannot pass.
- Added same-Worker automatic session recovery. An expired/lost session attempt is safely closed and requeued only to the session-affine Worker, preserving workspace metadata and rejecting the stale result; cross-Worker migration remains manual because that local workspace cannot be assumed to exist elsewhere.
- Added unified task runtime diagnostics across HTTP, status, CLI, MCP consumers, and Dashboard. The control plane now derives healthy lease, stale heartbeat, expired ownership, retry backoff, and same-Worker session wait states with actionable `nextAction` data; Dashboard separates operational attention from routing failures and no longer asks operators to compare raw timestamps.
- Added per-process Worker runtime identity and a strict installed-service restart drill. The VM must observe the home Worker offline, then record an unforgeable control-side runtime transition under the same signed token before a target-pinned task can prove execution under the new runtime.
- Added cross-site clock-skew diagnostics without relaxing replay protection. Health publishes a non-secret Control timestamp/policy, Worker preflight corrects it by measured round trip and fails before the signature boundary, and accepted signed registration/heartbeat evidence records the actual Control-minus-Worker timestamp delta for Dashboard and strict acceptance.

Azure control now binds native port 8765 to host loopback by default, while a bundled Caddy Compose overlay exposes 80/443, requires domain/proxy-secret configuration, forces authenticated trusted-proxy mode, overwrites forwarded evidence headers, and persists certificate state separately from control data.

- Unified the real cross-site acceptance checklist across CLI, Dashboard, HTTP, and MCP. The versioned runbook is resumable, includes previously easy-to-miss topology and revocation steps, comments operator placeholders, rejects unedited evidence, and ends at the strict completeness gate.
- Unified strict completion semantics across CLI, Dashboard, and MCP so a final claim always requires the deployment receipt, corrected generated examples that omitted it, and made deployment receipts expire after 24 hours with a five-minute future-clock allowance so stale boundary checks cannot certify a changed VM edge.
- Upgraded deployment receipts to v2 and bound strict acceptance to live Control hardening. The VM-side check reads sanitized Docker HostConfig plus PID 1 `/proc` evidence and fails when root identity, any capability set, writable rootfs/unexpected mount, unsafe tmpfs, or missing NoNewPrivs evidence remains; host mount source paths never enter the receipt.
- Added persistent home-Worker deployment wrappers to both portable bundle types: a non-root systemd service that waits for network-online, a current-user Windows logon task with bounded retry, and a current-user macOS LaunchAgent with validated private plist, failure-only restart, dedicated logs, and explicit root/LaunchDaemon refusal. All preserve the Agent user's HOME/PATH, wrap the same signed start path without copying credentials, and retain Worker identity/data on uninstall; bundle tests syntax-check generated shell/PowerShell scripts and assert service invariants.

Each process reports a protocol version, optional immutable CI build ID, and a deterministic cross-platform source fingerprint; registration persists Worker evidence, while capabilities, CLI, topology, Worker detail, and the strict cross-site gate distinguish compatible, source/build drift, protocol mismatch, and legacy unknown states.
